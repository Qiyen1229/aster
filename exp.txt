Aster 專案要求與更新標準作業摘要
====================================

一、你的核心要求與固定規範（已保存於 GEMINI.md）
------------------------------------------------
1. 版本控制原則
   - 未明確要求升級版號時，維持目前版本（4.1.56）不動。

2. Git 提交與推送規範
   - 每次完成程式或設定更新並通過驗證後，必須同步推送至 GitHub 遠端及 main 分支：
     - git add .
     - git commit -m "<簡潔明確的繁體中文更新說明>"
     - git push origin HEAD:main（若目前在功能分支上，亦同步 git push 目前分支）

3. 敏感與執行期檔案排除規範（避免外洩金鑰或 NAS git pull 衝突）
   - .env（含 .env.*，僅保留 .env.example）與 data/（含 server/data/，僅保留 data/api/.gitkeep）必須維持在 .gitignore 中，絕不可納入 Git 版控。
   - 執行 npm run pack:nas（產出 aster-nas.zip）時，絕不可包含 data/ 與 .env。

4. AI 模型路由與選型規範
   - 不使用中國模型。
   - 純文字任務：優先使用 Spark 自架 custom（Nemotron）。
   - 圖片（JPG / PNG / WebP）與 PDF 任務：優先使用 gemini，並略過純文字的 custom。
   - 語音轉錄（transcribe）：有設定 CLURE_ASR_URL 時優先 POST 本地 Breeze-ASR-25（multipart/form-data: file + language=zh，timeout 30 秒，輸出繁體阿拉伯數字不做簡轉繁）；失敗、超時、回空字串或未設定時自動 fallback 回 Gemini，並於日誌記錄 AI transcribe user_id=... provider=local/gemini ms=...。

三、每次更新後的標準步驟
------------------------------------------------
步驟 1｜執行驗證測試
- 前端檢查與建置（若有修改前端）：
  npm run check
  npm run build
- 後端測試（若有修改後端）：
  cd server && .venv/bin/pytest tests/ -q

步驟 2｜產出 NAS 部署包（不含 .env 與 data/）
- 執行：
  npm run pack:nas
- 確認輸出訊息顯示「不含 .env 與 data/」，且未把執行期資料夾打進壓縮檔。

步驟 3｜檢查暫存區並提交推送至 GitHub（含 main）
- 確認 .env 與 data/ 未進入暫存區，再執行：
  git add .
  git commit -m "<繁體中文更新說明>"
  git push origin HEAD:main

步驟 4｜伺服器端部署（VM 106 / NAS）
- 在主機端執行 git pull 更新程式碼（因 .env 與 data/ 已排除，不會覆蓋本地設定與資料庫）。
- 依更新範圍重啟對應服務（例如 docker compose up -d --build）。
